View of a board created while hidden

JSXGraph version: . Other versions: 1.14.1 · 1.14.0 · overview

Both cases use plain HTML and JSXGraph only: no Quarto, no iframe. Board (A) is visible from the start. Board (B) runs exactly the same code inside a display:none div, the way a board in a hidden tab or a closed <details> starts. Press Show and compare (B) with (A). Each status line is read 0.5 s after showing, after JSXGraph's resize observer has run.

1. A view set by the board code is lost (the important one)

The board code calls initBoard with one box and then sets another view right away, a common pattern: fit the view to the data, or pick it per exercise variant.

var board = JXG.JSXGraph.initBoard(id, {boundingbox: [-5, 5, 5, -5], axis: true});
board.setBoundingBox([0, 10, 10, 0], false);   // the view the author wants

(A) Visible from the start

(B) Hidden at creation, then shown

Expected: both show x from 0 to 10 and y from 0 to 10. Seen in 1.14.1: (B) shows the initBoard box [-5, 5, 5, -5]: the view set by the code is gone.

Why

While the container is hidden it is 0 × 0 px, so setBoundingBox computes unitX = 0 / 10 = 0 and the board's box becomes NaN. When the board is shown, updateContainerDims() sees the NaN box and rebuilds the units from this.attr.boundingbox (the 1.14.1 fix for hidden keep-aspect boards). That is the box given to initBoard, not the one the code asked for later.

Suggested fix

Remember a box that was requested while the container had no size, and use it when the board first gets a real size. A sketch against src/base/board.js of 1.14.1:

// In setBoundingBox(bbox, keepaspectratio, setZoom), after reading the container size:
if (!(w > 0 && h > 0)) {
    // Hidden container: remember the request instead of producing NaN units.
    this._pendingBoundingBox = { bbox: bbox.slice(), keepaspectratio: keepaspectratio };
    return this;
}
this._pendingBoundingBox = null;

// In updateContainerDims(), in the branch "If bounding box is not yet initialized":
if (this._pendingBoundingBox) {
    var p = this._pendingBoundingBox;
    this._pendingBoundingBox = null;
    this.canvasWidth = w;
    this.canvasHeight = h;
    this.setBoundingBox(p.bbox, p.keepaspectratio, 'keep');
} else {
    bbox = this.attr.boundingbox;
    // ... the existing 1.14.1 code ...
}

We tried this idea as a runtime patch on top of 1.14.1, in Chromium: (B) then shows [0, 10, 10, 0], like (A). The same loss happens in 1.14.0.

The same idea also covers zoomIn, zoomElements and other calls that end in setBoundingBox while the board is hidden. Calls that pass only the initBoard box are not affected, because the box is then the same.

2. A board defined by unitX/originX gets a non-finite view (exotic)

A board defined by units and origin instead of a box. We do not use this option in our courses: it came up in a systematic test of every way to define a board, so this case is for completeness.

var board = JXG.JSXGraph.initBoard(id, {unitX: 25, unitY: 25, originX: 40, originY: 200, axis: true});

(A) Visible from the start

(B) Hidden at creation, then shown

Expected: (B) has the same view as (A): the origin 40 px from the left and 200 px from the top, 25 px per unit. Seen in 1.14.1: (B)'s box is not finite when shown.

Why and a possible fix: no box was given, so the repair in updateContainerDims() has no meaningful attr.boundingbox to use. When the board was created with unitX/unitY/originX/originY, the repair could rebuild from those instead: this.unitX = attr.unitx; this.unitY = attr.unity; this.origin.scrCoords = [1, attr.originx, attr.originy];.
