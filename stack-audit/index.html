Public STACK question bank: mathematics and PRT audit

Pinned evidence, counterexamples, proposed repairs and regression cases

Published

October 20, 2026

This report is for STACK question-bank maintainers. Six parallel workers and a coordinating reviewer screened the public question collection shipped in maths/moodle-qtype_stack at commit 33383047af39c204bf4442802a058f8b918b2b1b. The scope includes standalone question XML, explanatory items and the four Moodle backup archives. Questions hosted elsewhere and other upstream branches are outside this snapshot.

The report contains 188 grouped findings about mathematics, random generators, model answers, potential response trees (PRTs), and feedback. Several source paths give credit to mathematically wrong responses; others reject valid answers or present false identities. One finding may cover several related files.

NoteEvidence and limits

This is a complete source inventory and broad static screen, followed by detailed source/mathematical review of candidate defects. Review depth varies by collection and is described below and in the sections. No Moodle/STACK/Maxima question executions were performed. A source-proven mismatch or mathematical counterexample is distinguished from a runtime-dependent candidate and a clarification about wording, domains or conventions. The absence of a finding is not a correctness certificate, exhaustive random-seed test, or claim that every diagram and legacy item has been deeply reviewed.

Are PRTs especially error-prone?

39 confirmed grouped findings concern PRT logic, affecting 55 standalone STACK records and 3 explicitly identified backup occurrences. Among the 2,585 standalone STACK records containing a PRT definition, the observed affected fraction is 2.1%. Among the 203 standalone STACK records with any confirmed defect, 27.1% have a confirmed PRT logic defect. These are question-level counts, not counts of faulty trees or nodes.

The audit demonstrates recurring PRT failure mechanisms, but does not establish that PRTs are more error-prone than other components. The screen was not a uniform, exhaustive component-by-component review, and no representative native test campaign was run. Wrong ordinary model answers, invalid random instances and incorrect MCQ keys are not relabelled as PRT logic errors merely because they affect grading. A fair comparison needs matched questions, explicit review of each component, comparable testing and independently checked positive cases. The 2.1% is an observed lower bound on the fraction of eligible standalone records affected by PRT defects, not an estimate of the true error rate. The 27.1% is a descriptive share among currently identified incorrect STACK records; it can move in either direction as additional defects are found.

Verification performed

Selected witnesses were independently checked with Python and, during source review, SymPy 1.14.0. The downloadable build checks use Python’s standard library and reproduce selected arithmetic and three XML score traces. The traces use supplied, mathematically justified node truth values: they test the actual graph root, transitions and score fields, not native answer tests or input validation.

PRT entry-node semantics were checked against questiontype.php, which derives the root from the graph. Candidates based on assuming node 0 always runs first were withdrawn. Independent re-review also removed apparent cross-product sign errors after following the full PRT paths, and downgraded convention-dependent or real-domain-dependent claims to clarifications.

Review covered mathematical statements, random-variable construction, PRT comparisons/reachable score paths, and worked feedback. Related defects are grouped below.

These are static source findings with mathematical counterexamples. Selected finite-support enumeration, arithmetic and symbolic differentiation were independently checked with Python/SymPy 1.14. AR-01: An incorrect fraction reaches a full-credit terminal

Status: Confirmed by static analysis.

Source: AlgMap-14-4.xml.

Problem: Both outcomes of the SingleFrac check at unique root node 0 lead to node 1, which assigns score 1 when lowesttermsp(ans) is true. The equivalence failure is therefore bypassed. SingleFrac itself checks equivalence.

Witness: An unrelated lowest-terms expression such as 1 fails the original comparison but follows the false branch to a true lowesttermsp check.

Fix: Terminate the false SingleFrac edge with zero; reach the form check only after equivalence succeeds.

Proposed native regression: Submit the correct simplified fraction, an equivalent unsimplified form, and unrelated answers 1 and 1/(a+b); assert unrelated answers score 0.

AR-02: Completed-square target has the wrong shift sign

Status: Confirmed by static analysis.

Source: AlgMap-15-8.xml.

Problem: The target uses a negative shift for a polynomial with linear coefficient +b.

Witness: a=2, b=8, c=1 gives 2v²+8v+1=2(v+2)²−7, whereas the target 2(v−2)²−7 has linear coefficient−8. The target-minus-original difference is−2bv.

Fix: Use shift+b/(2a) and derive the constant from the same identity.

Proposed native regression: Expand targets for all coefficient tuples; accept the correct shift and reject its opposite. Selected symbolic checking used SymPy, not native STACK.

AR-03: Linear-equation generator can divide by zero

Status: Confirmed by static analysis.

Source: AlgMap-9-5.xml.

Problem: The target divides by b1cf1+b2cf2 without excluding zero.

Witness: Allowed cf1=1,cf2=2,b1=−2,b2=1,k1=−1,k2=1 gives 3=0 and target calculation−3/0. Independent support enumeration found 29 coefficient tuples supporting a zero denominator.

Fix: Exclude zero resulting coefficients, or explicitly grade no-solution and infinite-solution cases.

Proposed native regression: Enumerate coefficient support; assert a nonzero divisor for every ordinary instance and instantiate the exhibited tuple.

AR-04: Simultaneous-equation generator permits nonunique solutions

Status: Confirmed by static analysis.

Source: AlgMap-12-1.xml.

Problem: Random coefficient matrices need not be nonsingular, but one constructed pair is graded as though unique.

Witness: With every matrix entry 2 and constructed solution [1,1], the RHS is [4,4]; [2,0] is another solution. Independent enumeration found 4 singular matrices among 24 possibilities.

Fix: Require nonzero determinant or grade the complete solution relation.

Proposed native regression: Enumerate matrix support and assert det(A)≠0; verify both exhibited solution pairs.

AR-05: Partial-fraction coefficients can divide by zero

Status: Confirmed by static analysis.

Source: Diagnostic_ALG-SPF_2.xml.

Problem: The coefficient formula divides by a*b−c, which may vanish and create repeated poles.

Witness: Allowed a=2, b=2, c=4 gives a*b−c=0.

Fix: Exclude equality or implement a repeated-factor decomposition.

Proposed native regression: Enumerate parameter support; assert distinct poles and finite coefficients, including the exhibited tuple.

AR-06: Exponent-law feedback confuses sum and product

Status: Confirmed by static analysis.

Source: AlgMap-1-5.xml; AlgMap-6-4.xml.

Problem: Feedback states ca+cb=c^(a+b).

Witness: c=2, a=2, b=3 gives 12 on the left and 32 on the right.

Fix: Write c^a*cb=c(a+b) and align the explanation with the actual operation.

Proposed native regression: Check unequal positive exponents and compare each worked equality symbolically.

AR-07: Hidden positivity changes a power identity

Status: Confirmed by static analysis.

Source: AlgMap-6-5.xml.

Problem: The PRT assumes c>0 but the prompt does not state that domain. The target simplification is invalid for arbitrary real c.

Witness: c=−1, multiplier coefficient 1, y=2, z=1/2 gives sqrt((−1)²)=1 but (−1)^(2*1/2)=−1.

Fix: State positive-real assumptions or preserve absolute values for the broader real domain.

Proposed native regression: Test positive and negative bases and fractional exponents; align stated domain and PRT assumptions.

AR-08: LCM explanation loses prime multiplicities

Status: Confirmed by static analysis.

Source: AlgMap-2-4.xml.

Problem: The explanation takes each distinct prime only once rather than taking the maximum exponent in either factorisation.

Witness: Allowed pair 4,18 has LCM 36=2²*3²; multiplying distinct primes gives 6. An earlier illustrative pair 4,8 was outside generator support and is not the regression witness.

Fix: Use maximum prime exponents from both numbers.

Proposed native regression: Test supported pair [4,18], coprime pairs and repeated prime factors; verify both LCM and explanation.

AR-09: Worked fraction expansion drops an outer constant

Status: Confirmed by static analysis.

Source: AlgMap-8-23.xml.

Problem: Feedback transforms (v−1/v)²+2 into an intermediate expression ending−2, dropping the outer+2. The final target is correct.

Witness: At v=1 the original is 2 and erroneous intermediate is 0. Correct expansion is v²+1/v².

Fix: Retain the outer+2 until it cancels the−2 from the square.

Proposed native regression: Compare adjacent displayed expressions for v≠0 and test v=1.
